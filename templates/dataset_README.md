# Synthetic UC1 / Submarine UAT dataset: $n banks, $rows_per_bank rows per bank

This dataset was generated by `generate.py` from the Coco-Submarine-UC1-UAT-Dataset-Generator repository, using `bank_bic_mapping_latest.csv` and `--rows-per-bank $rows_per_bank_raw`. Apart from that mapping, which is copied unchanged, every file in this folder is produced by the script.

- **$n banks:** $bank_list.
- **One submission cycle.**
- **Exactly $rows_per_bank rows in every bank's file.**
- **No duplicated accounts:** no bank's file lists the same account twice. An account can still be reported by several different banks, because that is what the shared list aggregates.

## Layout

```
README.md                                    this file
bank_bic_mapping_latest.csv                  the input mapping, copied unchanged (bic,bank_name,bank_id)
data/<bank_id>.csv                           one submission file per bank, $rows_per_bank rows each
expected_results/fraud_accounts_export.csv   the expected shared-list export, one row per account ($accounts rows)
```

## Input format

Each bank's file uses the standard UC1 submission format:

```
Account Number,BIC,Time Added,Modi Operandi,Priority Processing
```

- **Account Number** is `<BIC>` + `66` + the bank count as 2 digits (`$n2`) + a 10-digit counter, 22 characters in total.
- **BIC** is the 8-character BIC of the bank where the account is **held**, not the bank reporting it. It is always the first 8 characters of the account number. An account has exactly one BIC, the same one in every bank's file that lists it.
- **Time Added** is a Unix timestamp within the week starting Mon 2026-11-02 00:00 UTC (`$t0`).
- **Modi Operandi** holds one to three values from the MO list below, separated by `;`. A value containing a comma is CSV-quoted normally (`"Überweisung, noch unbekannter MO"`), never as `"""…"""`.
- **Priority Processing:** `$upper` writes `TRUE`/`FALSE`, and every other bank writes `True`/`False`. This deliberately mirrors the inconsistent casing between real banks.

## Banks and BICs

$banks_table

`#` is the bank's position in the mapping (the order each `bank_id` first appears). The named accounts below are built from these positions.

All of a bank's BICs are equal. Each one maps directly to its `bank_id` and display name, and no BIC is ever rewritten into another. Bulk accounts draw their holding BIC at random (seeded) from the relevant bank's BICs, and the data is not required to use every BIC in the mapping.

Accounts **held outside the participating banks** use these BICs, none of which is in the mapping: $outside_list.

## Modi operandi

Every bank draws from the same built-in list of $mo_count MOs. No external MO list is used.

$mo_list

## How the data is built

### Blocks

$block_table

The multi-reporter blocks are sized from the rows-per-bank value first. Each bank's remaining rows are then filled with single-reporter accounts (75 % own, 10 % held at another participating bank, 15 % held outside), so every file ends up with exactly $rows_per_bank rows.

Every 10th account in each multi-reporter block has **tied timestamps**: all of its reporters submitted in the same second. Bulk tied times sit in their own band, from $t_tied upwards and above every other time, so a bulk tie can be recognised from `Time Added` alone. Elsewhere in the bulk data, no two rows share a timestamp. The one named tie (account 11 below) stays in its named-account time slot instead.

### Named scenario accounts

These accounts have fixed content and counters 1 upwards. `Reporting banks` lists bank IDs in export order: time, then display name.

$named_table

### Checked across the whole dataset

- **Own reports only:** a bank's file contains only the accounts that bank itself reported.
- **Idempotence:** aggregating the same submissions twice gives identical output.
- **Every pair of banks** corroborates at least one account, and every report count from 1 to $n occurs.

### What this dataset does not cover, and why

| Scenario | Reason |
|---|---|
| S1 new account, S3 maintained, S4 one bank stops / other continues, S5 last report removed, S6 missed cycle, S8 re-listing | Each needs at least two cycles, and this dataset has one. |
| S7 corrective resubmission | Production has no such concept. |
| S11, SC-12, SC-13 duplicate rows within one bank's file | Excluded on purpose: "no duplicated accounts". |

## Expected results

`expected_results/fraud_accounts_export.csv` follows the current platform export shape:

```
Account Number, Holding Bank BIC, Number of Reports, Priority Processing,
Report i Reporting Bank, Report i Time, Report i Modus Operandi, Report i Priority Processing   (i = 1..$fan)
```

- **Holding Bank BIC** is the account's BIC exactly as submitted. Production stores `holding_bank_bic = BIC` with no resolution.
- **Number of Reports** is the number of banks that reported the account.
- **Priority Processing** is `Yes` if *any* report says `True` (OR).
- **Report i Modus Operandi** is that bank's MO string exactly as submitted.
- Reporting banks use their display names, and booleans are `Yes`/`No`. Unused report groups are left empty.
- **Is Own Bank** is not included. The platform adds it per requesting bank, because it depends on who downloads the export.
- **Order:**
  - Rows are sorted by earliest report time, newest first, then by account number.
  - Report groups are sorted by time, then by bank display name.
  - The platform does not promise either order. Compare by account number, and treat each row's report groups as an unordered set.

## Regenerating

From the repository root, the folder that contains `generate.py`:

```
python generate.py <this folder>/bank_bic_mapping_latest.csv --rows-per-bank $rows_per_bank_raw
```

On the same Python version, this writes a new run folder whose files are byte-identical to this one's. The script is deterministic: its RNG is seeded from the mapping file's bytes and the rows-per-bank value, and the data never reads the clock.

Before a run reports success, it reads every written file back from disk and asserts:
- each file has exactly $rows_per_bank rows;
- there are no repeats within a file;
- each file holds only its own bank's reports;
- each account has one BIC;
- every BIC is 8 characters and comes from the mapping or the outside list;
- account numbers are 22 characters and start with their BIC;
- every MO passes the platform's MO validator regex;
- boolean casing is correct for each bank;
- the priority thirds hold in every block of 3 or more reporters;
- every named account has its expected values;
- every pair of banks corroborates at least once;
- every report count from 1 to $n occurs;
- the on-disk data aggregates exactly to the expected export;
- aggregation is idempotent;
- the copied mapping is byte-identical to the input.
